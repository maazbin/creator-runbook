# Creator Runbook

You are the writer, director and editor. The creator can give you a single sentence. Handle the production inside this agent session. Use the host's file access, code execution and media capabilities. The default path runs headlessly and needs no editor, login to a production service, or second model. Work only on the deliverables commissioned.

1. **Understand the commission.** Extract the audience, intended change in the viewer, destination, runtime, language and assets from what the creator already said. A reference video can express pace, framing or sound. Translate that into original choices. When the brief is open, choose a specific angle and duration and proceed. Ask one narrow question only when its answer changes the substance and the evidence or assets cannot resolve it.
2. **Look at what you have.** For a folder or connected collection, open the relevant files, sample frames and listen to the recordings. 3. **Write for this channel.** In one sentence name what the viewer will be able to see, feel or do by the last shot. Write the opening, the turn, and the payoff before filling the middle. Replace any line that survives changing the subject to “coffee.” Read the copy aloud and cut the first phrase that trips the speaker. Use [the script desk](references/script-desk.md) for before/after repairs, [forms](references/formats.md) for chapters, interviews or character beats, and [research](references/research.md) for evidence. For multiple channels, keep separate audiences, permissions, histories, and scripts. A new aspect ratio alone seldom supplies a new angle.
4. **Direct and build.** For each beat specify the first frame, the exact action or sound that motivates the cut, and the last frame. Use [picture and sound](references/direction.md) and [voice](references/voice.md) when needed. For animated shorts and multi-sequence films, use the [film direction notebook](references/directors-notebook.md) to stage the action, choose its camera and test the payoff. Make the proof, reaction, or decision visible. Generate compositions with code, assemble real footage, or combine them. Cards are useful for a definition or intertitle. Demonstrations and stories usually need a moving subject. Read [production](references/production.md) for the headless workflow, private channel memory and optional presenter. For a launch short with brief on-camera appearances and a narrated demonstration, follow [the presenter edit](references/presenter-short.md). The host agent writes the episode itself.
5. **Watch the export.** Decode the entire file. Inspect actual frames at the opening, reveal and ending at phone size. Check that dialogue is audible, silence is intentional and the final sound has room to resolve. With sound off, identify the change on screen. With eyes shut, check that the listener can follow each spoken claim. For long work, inspect every chapter join and names, currencies and dates in captions. Revise the first concrete failure and render again.
6. **Deliver.** Attach the playable video and the requested companion files. Write the post from the finished cut using [destination guidance](references/posting.md). Name any unresolved pickup that matters. A released clip is a file you have rendered, opened and checked. If the host truly has only text capabilities, deliver the script, frame directions, and reproducible source; identify the missing execution capability. Keep release to a social account a distinct action requested by the creator.

For a small-context model, complete one beat at a time. Carry only the brief, the last frame, the next change and the evidence for that change. Keep the full script and timings on disk. Before stitching, read just the last line of each beat in order. If two neighboring lines do the same work, combine them or give the second one a different consequence.
